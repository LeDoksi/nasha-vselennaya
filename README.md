# 💜 Наша вселенная

Сайт для Гоши и Даши. Запускается локально — без интернета.

## 🚀 Как открыть

Двойной клик по файлу `index.html` — откроется в браузере.

## 📂 Структура

```
наша-вселенная/
├── index.html      ← главная страница
├── styles.css      ← стили
├── app.js          ← собран из src/ (node build.js)
├── build.js        ← сборка src/*.js → app.js
├── run-tests.cmd   ← двойной клик: запуск проверок
├── README.md
├── PROJECT-MEMORY.md  ← памятка для разработки: схема данных, механики, тесты
├── src/            ← модули (00-core, 10-vault, …, 95-sync)
├── tests/
│   ├── uni-smoke.js   ← смоук-тест (372 проверки)
│   ├── uni-dnd.js     ← drag&drop (60)
│   ├── repro-event-btn.js ← регрессия события (15)
│   └── uni-hash.js    ← старт по ссылке #/…
└── music/          ← сюда положить нашу песню
    └── nasha-pesnya.mp3  (mp3-файл «Ошибся номером» — ТБКС)
```

## ✨ Что умеет

- **Главная** — счётчик «дней вместе», напоминания о ближайших событиях (за 2 недели), **комплимент дня** 💌 (меняется каждый день), **таймер до ближайшего события/свидания** ⏳ и **3 парящих фото** вокруг блока приветствия (5 «гнёзд», плавная смена). Если сегодня важный день — **конфетти** 🎉.
- **Кто ты?** — при первом входе сайт спрашивает «Кто сейчас с нами?» (Гоша/Даша). Чип в шапке показывает пользователя и позволяет переключиться.
- **Свидания** — кнопка «💘 Назначить свидание»: дата, время, место, идея и **от кого приглашение** (Гоша/Даша/вместе). Пригласивший уже согласен («💌 позвал/позвала»), а **«Да 👍 / Нет 👎»** отвечает только приглашённый. Когда оба говорят «да» — конфетти и бейдж «💞 Мы идём на свидание!».
- **Календарь** — свои памятные даты: жми на день → добавляй событие. Можно **редактировать** (✏️) и удалять, повторять каждый год.
- **Заметки** — общее место для записок, с закреплением 📌.
- **Списки** — покупки 🛒 и дела ✅ отдельно.
- **Хотелки** 🎁 — список желаний: описание (обязательно), фото и ссылка (по желанию). Вишлист **разделён по людям**: «👦 Хотелки Гоши» и «👧 Хотелки Даши» — у каждого свой список, отметка «исполнено» ✅.
- **Фото** — загрузка с компьютера, **лейблы** 🏷 (у фото их несколько, фильтр сверху: «Все фото» или один лейбл), **выбор нескольких** фото и добавление лейбла сразу всем, удаление лейблов без вреда фото, закрепление ⭐, **перетаскивание** для порядка, просмотр на весь экран. На телефоне под главной — горизонтальная лента фото.
- **Песня** — наш трек; положи mp3 в `music/nasha-pesnya.mp3`, чтобы играл офлайн.
- **Настройки** — резервная копия данных (скачать/загрузить JSON) + **напоминание**, если копии давно не было; счётчик занятого места в браузере; **тёмная тема** 🌙.

## 💾 Где хранятся данные

Все данные зашифрованы (AES-256) и живут **локально**: сейф — в браузере
(localStorage), фото — в IndexedDB. Никто, кроме вас, их не прочитает — нужен пароль.

- Регулярно делай копию через **Настройки → «Скачать копию»** (файл включает и фото).
- **Синхронизация с телефоном** — через облако Firebase (см. ниже). Без неё данные
  остаются на одном устройстве.

## ☁️ Синхронизация (Firebase + Яндекс.Диск)

Сайт синхронизируется между устройствами через **Firebase Realtime Database**
(сейф-данные, бесплатный тариф) и **Яндекс.Диск** (фото: оригиналы + миниатюры).
В облако уходят **только зашифрованные данные** — серверы видят шифртекст,
прочитать его без вашего пароля невозможно (zero-knowledge). Конфликты решаются
по правилу «последняя правка выигрывает».

> Почему Яндекс.Диск, а не Firebase Storage: Firebase Storage работает только на
> платном тарифе Blaze (оплатить из России не получится). Яндекс.Диск — бесплатно
> (10 ГБ), и фото в нём лежат уже зашифрованными.

### B1. Как подключить (один раз, ~15 минут)

1. Зайди на https://console.firebase.google.com (любой Google-аккаунт).
2. **Создать проект** (имя любое, например `nasha-vselennaya`), Analytics можно не включать.
3. В проекте: **Build → Realtime Database → Создать базу данных** → регион `europe-west1`
   (ближе к нам) → начать в **locked-режиме**.
4. Открой вкладку **Rules** и вставь:
   ```json
   {
     "rules": {
       "vaults": {
         "$any": {
           ".read": "auth != null",
           ".write": "auth != null"
         }
       }
     }
   }
   ```
   > Данные на сервере зашифрованы, поэтому доступ открыт любому анониму — но только
   > ваш пароль открывает сейф. Так оба устройства (Гоша и Даша) видят общий vault.
5. **Build → Authentication → Sign-in method → Anonymous** → включить.
6. **Яндекс.Диск** (фото) — зайди на https://oauth.yandex.ru (любой аккаунт Яндекса):
   a. **Создать приложение**: название `nasha-vselennaya`, платформа «Веб-сервисы»,
      Callback URI `https://oauth.yandex.ru/verification_code`.
   b. В «Доступ к данным» отметь **«Яндекс.Диск REST API. Доступ к папке
      приложения»** (scope `cloud_api:disk.app_folder`) — приложение увидит только
      свою папку `/Приложения/nasha-vselennaya/`, а не весь Диск.
   c. Сохрани приложение → на странице приложения нажми **«Выпустить токен»** →
      скопируй токен (большая строка).
   > 🔐 Токен даёт доступ только к папке приложения, а фото в ней — зашифрованы
   > (AES-256). Даже если токен утечёт, содержимое без пароля не прочитать.
7. **Project settings ⚙ → Общие → Ваши приложения → Добавить приложение (Web, `</>`)**
   → скопируй объект `firebaseConfig`.
8. В `src/95-sync.js` вставь оба значения:
   ```js
   const FIREBASE_CONFIG = { apiKey: '…', authDomain: '…', databaseURL: '…', projectId: '…', … };
   let YANDEX_DISK_CONFIG = { token: 'твой_токен_с_oauth.yandex.ru', basePath: '/photos' };
   ```
   Фото уедут в папку `/Приложения/nasha-vselennaya/photos/` — миниатюры, показ-версии
   и оригиналы, всё в виде шифртекста.
9. Пересобери: `node build.js`. Открой сайт, войди → **Настройки → Синхронизация**:
   «Синхронизировано ✅». То же самое на телефоне — данные объединятся.

> ⚠️ `apiKey` — не секрет (данные защищены правилами и шифрованием). Но не делись
> ссылкой на сайт с посторонними — внутри личные истории 💜

## 🌐 Выложить в интернет (GitHub Pages)

Сайт статический — его можно бесплатно опубликовать на **GitHub Pages**
(адрес с HTTPS, никаких платных серверов). Тогда с телефона ты просто
открываешь ссылку — всё подтянется из облака.

1. Заведи аккаунт на https://github.com (бесплатно, без карты).
2. Нажми **New repository** → имя, например `nasha-vselennaya` → **Private** →
   **Create repository**. Оставь его пустым (не создавай файлы).
   GitHub Pages работает и на приватных репозиториях: код остаётся только у тебя,
   а сайт по ссылке будет доступен тем, кому ты её дашь.
3. В папке проекта (PowerShell) один раз подключи и отправь репозиторий:
   ```powershell
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/nasha-vselennaya.git
   git push -u origin main
   ```
   (Git попросит войти в GitHub — откроется окно браузера, разреши.)
4. На GitHub: **Settings → Pages → Source: GitHub Actions**.
5. Репозиторий **Actions**: запустится сборка, и сайт опубликуется сам.
6. Ссылка вида `https://ТВОЙ_ЛОГИН.github.io/nasha-vselennaya/` — открой её
   на телефоне и войди паролем: данные из облака восстановятся.

Дальше просто: любые изменения → `git push` → сайт обновится автоматически.

> 🔒 Что увидят посторонние, если узнают ссылку: `apiKey` Firebase и токен
> Яндекс.Диска в `app.js` — это нормально для браузерного приложения, безопасность
> держится на **шифровании + пароле** (сейф без пароля не прочитать, токен видит
> только папку приложения). Худшее, что может сделать «чужой», — записать мусор
> вместо сейфа: сайт его не применит и не затрёт свой, просто появится конфликт,
> который лечится кнопкой «Синхронизировать сейчас». Поэтому держи ссылку только
> для своих и не забывай делать копию в Настройках 💜
>
> 🎵 Песня (`music/`) в публикацию не входит — она личная и в git не хранится.
> Если хочется, чтобы она играла и на телефоне — добавь файл в репозиторий
> (`git add music/nasha-pesnya.mp3`), тогда он попадёт и на сайт.
