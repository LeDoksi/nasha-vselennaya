# 💜 Наша вселенная

Сайт для Гоши и Даши. Запускается локально — без интернета.

## 🚀 Как открыть

Двойной клик по файлу `index.html` — откроется в браузере.

## ✨ Что умеет

- **Главная** — единый hero-блок: заголовок, имена, **кольцо прогресса до годовщины** с количеством дней/лет вместе, **коллаж из 3 случайных фото** (приоритет — фото «в этот день»), статистика (фото/события/свидания/заметки/хотелки) и события прошлых лет чипами «✨ В этот день» — раньше это были два разных блока с задвоенным счётчиком дней, теперь один. Ниже — **комплимент дня** 💌 (меняется раз в сутки) и **таймер до ближайшего события/свидания** ⏳. Если сегодня важный день — **конфетти** 🎉.
- **Вход** — свой пароль у каждого (Гоша/Даша), данные видны только тому, кто знает пароль. Обновление страницы **не разлогинивает** (сессия на время открытой вкладки; закрыл вкладку/браузер — пароль снова нужен). Кнопка выхода — в Настройках («🔒 Выйти»).
- **Свидания** — кнопка «💘 Назначить свидание»: дата, время, место, идея. Свидание всегда от имени вошедшего — пригласивший уже согласен («💌 позвал/позвала»), а **«Да 👍 / Нет 👎»** отвечает только приглашённый. Когда оба говорят «да» — конфетти.
- **Календарь** — свои памятные даты: жми на день → добавляй событие. Можно **редактировать** (✏️) и удалять, повторять каждый год, длительные события (диапазон дней).
- **Заметки** — общее место для записок: закрепление 📌, **правка на месте** (✏️ или двойной клик), **перетаскивание** для порядка.
- **Списки** — произвольные списки (не только «покупки»/«дела» — любое название), **перетаскивание** карточек списков и подзадач внутри списка для порядка, **правка названия списка** и текста подзадачи на месте, «✔ Выполнить список» одним нажатием.
- **Хотелки** 🎁 — список желаний: описание (обязательно), фото и ссылка (по желанию). Вишлист **разделён по людям**: «👦 Хотелки Гоши» и «👧 Хотелки Даши» — у каждого свой список, исполнить хотелку может только партнёр.
- **Фото** — загрузка с компьютера, **цветные лейблы** 🏷 (у фото их несколько, фильтр сверху: «Все фото» или один лейбл — клик по чипу всегда просто фильтрует). Управление лейблами (создание, переименование на месте, цвет, удаление) — в отдельной модалке «🏷 Лейблы», не смешано с применением к фото. Применение лейблов к фото — через попап-чек-лист (тап по лейблу навешивает/снимает сразу; можно создать новый лейбл и сразу применить), открывается из выбора нескольких фото или прямо из полноэкранного просмотра одного фото; либо классическим перетаскиванием фото на чип и обратно. Выбор нескольких фото — **удалить выбранные** или добавить лейбл всем сразу. Закрепление ⭐, **перетаскивание** для порядка (фото/список/подзадачи/заметки — везде одна и та же механика, SortableJS), просмотр на весь экран.
- **Настройки** — резервная копия данных (скачать/загрузить JSON) + **напоминание**, если копии давно не было; счётчик занятого места в браузере; **тёмная тема** 🌙; управление паролями и синхронизацией.

Нижняя навигация на телефоне — все вкладки в один ряд иконками (без вкладки «Ещё»); «⚙️ Настройки» — отдельной иконкой в шапке, а не среди вкладок.

## 💾 Где хранятся данные

Все данные зашифрованы (AES-256) и живут **локально**: сейф — в браузере
(localStorage), фото — в IndexedDB. Никто, кроме вас, их не прочитает — нужен пароль.

- Регулярно делай копию через **Настройки → «Скачать копию»** (файл включает и фото).
- **Синхронизация с телефоном** — через облако Firebase (см. ниже). Без неё данные
  остаются на одном устройстве.

## ☁️ Синхронизация (Firebase + Yandex Object Storage)

Сайт синхронизируется между устройствами через **Firebase Realtime Database**
(крошечный зашифрованный сейф-JSON, бесплатный тариф) и **Yandex Object
Storage** (фото: оригиналы + показ-версии + миниатюры). В облако уходят
**только зашифрованные данные** — серверы видят шифртекст, прочитать его без
вашего пароля невозможно (zero-knowledge). Конфликты решаются по правилу
«последняя правка выигрывает».

> Почему Yandex Object Storage, а не Firebase Storage: Firebase Storage работает
> только на платном тарифе Blaze (оплатить из России не получится). Yandex Object
> Storage — бесплатный tier, S3-совместимый, и фото в нём лежат уже зашифрованными.
>
> **Ключей доступа в коде нет.** Сайт статический и отдаётся браузеру любого
> посетителя — значит, любой секретный ключ, вписанный в JS, сразу станет
> публичным («Просмотр кода страницы»). Вместо секрета бакет настроен так,
> что читать/писать/удалять объекты в папке `photos/` может кто угодно
> анонимно — ровно как и с Firebase RTDB ниже (`auth != null`, доступно
> любому анониму). Это безопасно, потому что содержимое — не открытые фото,
> а AES-GCM шифртекст: без вашего пароля прочитать нельзя. Риск, который
> это несёт: кто-то, кто узнает имя бакета, теоретически может залить туда
> мусор или удалить объекты (не прочитать — только испортить); отсюда ниже
> совет включить версионирование как страховку.

### B1. Firebase (сейф) — один раз, ~10 минут

1. Зайди на https://console.firebase.google.com (любой Google-аккаунт).
2. **Создать проект** (имя любое, например `nasha-vselennaya`), Analytics можно не включать.
3. В проекте: **Build → Realtime Database → Создать базу данных** → регион `europe-west1`
   (ближе к нам) → начать в **locked-режиме**.
4. Открой вкладку **Rules** и вставь:
   ```json
   {
     "rules": {
       "vaults": {
         "$any": {
           ".read": "auth != null",
           ".write": "auth != null"
         }
       }
     }
   }
   ```
   > Данные на сервере зашифрованы, поэтому доступ открыт любому анониму — но только
   > ваш пароль открывает сейф. Так оба устройства (Гоша и Даша) видят общий vault.
5. **Build → Authentication → Sign-in method → Anonymous** → включить.
6. **Project settings ⚙ → Общие → Ваши приложения → Добавить приложение (Web, `</>`)**
   → скопируй объект `firebaseConfig`.
7. В `src/95-sync.js` вставь значение:
   ```js
   let FIREBASE_CONFIG = { apiKey: '…', authDomain: '…', databaseURL: '…', projectId: '…', … };
   ```

> ⚠️ `apiKey` — не секрет (данные защищены правилами и шифрованием). Но не делись
> ссылкой на сайт с посторонними — внутри личные истории 💜

### B2. Yandex Object Storage (фото, чтение) — один раз, ~15 минут

> ⚠️ **Важно понимать:** Yandex Object Storage разрешает делать бакет публичным
> **на чтение**, но НЕ поддерживает анонимную **запись** (`PutObject`/`DeleteObject`),
> даже если политика бакета формально её разрешает — на практике сервер всё
> равно ответит `403`, проверено. Поэтому здесь настраивается только чтение;
> запись (загрузка/удаление фото) идёт через отдельную Cloud Function — B3 ниже.

1. Зайди в [консоль Yandex Cloud](https://console.yandex.cloud) → **Object Storage**
   → **Создать бакет**: имя, например `nasha-vselennaya` (должно совпадать с
   `YANDEX_CLOUD_CONFIG.bucket` в `src/95-sync.js`), доступ — «Приватный»
   (точнее настроим ниже), класс хранилища — «Стандартный».
2. Настрой **CORS** (бакет → **Настройки → CORS** либо **Безопасность → CORS**,
   в зависимости от версии консоли), разреши `GET`, `PUT`, `DELETE` с origin
   твоего сайта (`https://ТВОЙ_ЛОГИН.github.io`) или `*`, если удобнее.
3. **Настройки бакета → Основные → Доступ**: переключи **«Чтение объектов»**
   и **«Чтение списка объектов»** на **«Для всех»** (это тот самый переключатель,
   без которого чтение не заработает, даже если политика ниже верна). «Чтение
   настроек» можно оставить «С авторизацией».
4. **Безопасность → Политика доступа → Настроить доступ** — три правила:
   - **Правило 1** (чтение фото): Результат «Разрешить», Пользователь «Все
     пользователи», Действие `GetObject`, Ресурс `nasha-vselennaya/photos/*`.
   - **Правило 2** (список файлов): Результат «Разрешить», Пользователь «Все
     пользователи», Действие `ListBucket`, Ресурс `nasha-vselennaya` (**без**
     `/photos/*` на конце — `ListBucket` действует на весь бакет, папка
     задаётся условием), плюс «Добавить условие»: Ключ `prefix`, Оператор
     `StringLike`, Значение `photos/*`.
   - **Правило 3** — нажми кнопку **«Добавить правило для доступа из консоли»**
     (она подставит правило сама). Без него после сохранения своей политики
     консоль перестанет пускать тебя в разделы «Объекты»/«CORS» этого же
     бакета — задокументированная особенность Yandex Object Storage.
   Сохрани. В виде JSON (если понадобится через CLI/API) это выглядит так:
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       { "Effect": "Allow", "Principal": "*", "Action": "s3:GetObject",
         "Resource": "arn:aws:s3:::nasha-vselennaya/photos/*" },
       { "Effect": "Allow", "Principal": "*", "Action": "s3:ListBucket",
         "Resource": "arn:aws:s3:::nasha-vselennaya",
         "Condition": { "StringLike": { "s3:prefix": "photos/*" } } },
       { "Sid": "AllowAWSServices", "Effect": "Allow", "Principal": "*", "Action": "s3:*",
         "Resource": ["arn:aws:s3:::nasha-vselennaya/*", "arn:aws:s3:::nasha-vselennaya"],
         "Condition": { "Bool": { "aws:PrincipalIsAWSService": "true" } } }
     ]
   }
   ```
5. Версионирование (Настройки → Версионирование) — необязательно, но полезно
   как страховка от случайного/злонамеренного удаления; стоит места в бакете,
   поэтому можно пропустить (мы пропустили).
6. В `src/95-sync.js` проверь/поставь имя бакета:
   ```js
   let YANDEX_CLOUD_CONFIG = { bucket: 'nasha-vselennaya', region: 'ru-central1', signFnUrl: '' };
   ```
   `signFnUrl` заполнится в шаге B3 — без него чтение фото уже работает, а
   запись (загрузка новых фото) — ещё нет.

### B3. Cloud Function `photo-sign` (фото, запись) — один раз, ~15 минут

Раз анонимная запись в бакет невозможна (см. предупреждение в B2), загрузка/
удаление фото идёт в два шага: браузер просит у маленькой серверной функции
**подписанную (presigned) ссылку** с временем жизни 60 секунд, затем сам
загружает файл по этой ссылке напрямую в бакет. Секретный ключ хранится
только в переменных окружения функции — в браузер он никогда не попадает.
Код функции — `functions/photo-sign/index.js` в этом репозитории.

1. **Сервисный аккаунт и статический ключ.** Если ещё нет сервисного аккаунта
   с правами на бакет — **Object Storage → бакет → Безопасность → Права
   доступа → Назначить роли** → создай сервисный аккаунт (или используй
   существующий) с ролью **`storage.editor`** на бакете. Дальше у этого
   сервисного аккаунта: **Сервисные аккаунты → выбрать аккаунт → Создать
   новый ключ → Создать статический ключ доступа** → сохрани `Key ID` и
   `Secret key` (секрет показывается один раз!).
2. **Создать функцию:** консоль → **Cloud Functions → Создать функцию** →
   имя, например `photo-sign` → среда выполнения **Node.js** (последняя
   версия) → в редакторе кода вставь содержимое `functions/photo-sign/index.js`
   → **Точка входа**: `index.handler`.
3. **Переменные окружения** функции (там же, при создании/редактировании версии):
   - `YC_S3_KEY` = Key ID из шага 1
   - `YC_S3_SECRET` = Secret key из шага 1
   - `YC_BUCKET` = `nasha-vselennaya` (или имя твоего бакета)
   - `YC_REGION` = `ru-central1`
   - `ALLOWED_ORIGIN` = `https://ТВОЙ_ЛОГИН.github.io` (или `*`)
4. Сохрани версию функции. На странице функции (**Обзор**) включи
   **«Публичная функция»** — без этого вызвать её сможет только тот, у кого
   есть IAM-токен, то есть сайт не сможет.
5. Скопируй **публичный URL функции** (вида
   `https://functions.yandexcloud.net/<идентификатор>`) и вставь в
   `src/95-sync.js`:
   ```js
   let YANDEX_CLOUD_CONFIG = { bucket: 'nasha-vselennaya', region: 'ru-central1',
     signFnUrl: 'https://functions.yandexcloud.net/твой-идентификатор' };
   ```
6. Пересобери: `node build.js`. Открой сайт, войди, загрузи тестовое фото →
   **Настройки → Синхронизация**: «Синхронизировано ✅». Проверь на втором
   устройстве/браузере, что фото появилось.

> 🔒 `signFnUrl` — не секрет (это просто адрес, как и `apiKey` Firebase);
> секрет — `YC_S3_KEY`/`YC_S3_SECRET`, они живут только в переменных
> окружения функции и никогда не попадают в код сайта.

## 🌐 Выложить в интернет (GitHub Pages)

Сайт статический — его можно бесплатно опубликовать на **GitHub Pages**
(адрес с HTTPS, никаких платных серверов). Тогда с телефона ты просто
открываешь ссылку — всё подтянется из облака.

1. Заведи аккаунт на https://github.com (бесплатно, без карты).
2. Нажми **New repository** → имя, например `nasha-vselennaya` → **Create repository**.
   Оставь его пустым (не создавай файлы).
   > Репозиторий этого проекта — **публичный** (приватный + бесплатный GitHub Pages
   > не сочетаются). Поэтому код и `PROJECT-MEMORY.md` (с личными деталями) видны
   > всем, у кого есть ссылка на репозиторий — не только на сайт. Убедись, что в
   > коде и истории коммитов нет ключей/токенов (см. предупреждение ниже), и не
   > публикуй ссылку на сам репозиторий без необходимости.
3. В папке проекта (PowerShell) один раз подключи и отправь репозиторий:
   ```powershell
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/nasha-vselennaya.git
   git push -u origin main
   ```
   (Git попросит войти в GitHub — откроется окно браузера, разреши.)
4. На GitHub: **Settings → Pages → Source: GitHub Actions**.
5. Репозиторий **Actions**: запустится сборка, и сайт опубликуется сам.
6. Ссылка вида `https://ТВОЙ_ЛОГИН.github.io/nasha-vselennaya/` — открой её
   на телефоне и войди паролем: данные из облака восстановятся.

Дальше просто: любые изменения → `git push` → сайт обновится автоматически.

> 🔒 Что увидят посторонние, если откроют сайт или заглянут в код: `apiKey`
> Firebase и имя бакета Yandex Object Storage в `app.js` — в коде нет ни одного
> секретного ключа (см. раздел про синхронизацию выше), поэтому смотреть там
> нечего. Безопасность держится на **шифровании + пароле**: сейф без пароля не
> прочитать, фото — тоже шифртекст. Худшее, что может сделать «чужой», —
> записать мусор вместо сейфа (сайт его не применит и не затрёт свой, появится
> конфликт, который лечится кнопкой «Синхронизировать сейчас») или намусорить/
> удалить объекты в бакете фото (для этого и включено версионирование в B2).
> Поэтому держи ссылку на сайт только для своих и не забывай делать копию в
> Настройках 💜
