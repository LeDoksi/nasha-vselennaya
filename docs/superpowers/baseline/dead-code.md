# Мёртвый CSS: что удалено и что осталось кандидатом

Задача: NV-13, фаза 0, шаг 4 («Честный проход по мёртвому коду»). Разведка
регуляркой (Codebase Report) до этой задачи насчитала 55 «мёртвых» CSS-классов,
из которых 45 оказались живыми при ручной проверке, и 143 «мёртвые» функции,
из которых почти все живые — сама по себе регулярка ничего не доказывает, нужны
были инструмент (Playwright CSS Coverage) и глаза.

## Метод

1. **`tools/css-coverage.js`** (одноразовый скрипт) поднимает `styles.css`,
   обходит все 8 экранов стенда (`tools/demo.html`) в обоих размерах
   (phone/desk) и обеих темах (dark/light) — как `tools/shots.js` — с
   `page.coverage.startCSSCoverage()` включённым на каждой странице. На выходе:
   список листовых CSS-правил (селектор + декларации, без учёта
   `@media`/`@keyframes`-контейнеров как таковых), которые ни разу не
   совпали ни с одним элементом ни на одном из 32 прогонов. Полный список —
   `docs/superpowers/baseline/css-coverage-unused.json` (227 правил из 525).
2. Одиннадцать классов, названных спекой (раздел 4.1) как «эпоха сейфа»,
   сверены отдельно — прямым `grep` по `index.html app.js src/*.js` (и
   дополнительно по `tools/demo.html tools/demo-fixtures.js`, на случай если
   стенд их всё ещё рисует сам). Все одиннадцать дали **ноль совпадений** —
   значит, ни один элемент в реальном приложении (и в стенде) не может
   получить эти классы, покрытие браузером тут просто подтверждает то, что
   уже видно по тексту.

## Что удалено (шаг 3)

Все 11 названных спекой классов — они же независимо подтверждены нулевым
покрытием CSS coverage. Это старый интерфейс выбора пользователя и подсказки
на гейте (до перехода на вход через Google, см. комментарий в `index.html`
над `.auth-screen`: «Гейт: вход только для двух Google-аккаунтов»), плюс два
несвязанных остатка (`.btn-plain`, `.empty-state .es-emoji`):

| Класс | Было (styles.css) | Причина мертвизны |
|---|---|---|
| `.auth-who`, `.auth-user`, `.auth-user.auth-on`, `.auth-label`, `.auth-hint` | блок «Личный кабинет: замок и создание пароля» | UI выбора пользователя/пароля заменён на кнопку «Войти через Google» — в `index.html` этих классов больше нет |
| `[data-theme="dark"] .auth-user` | тёмная тема того же блока | тот же UI |
| `.modal-center`, `.user-sub`, `.user-btns`, `.user-btn`, `.user-btn:hover` | стили карточек выбора пользователя | часть того же снесённого UI |
| `[data-theme="dark"] .user-btn:hover` | тёмная тема | тот же UI; сама правка была точечной — в `[data-theme="dark"] .note.pinned,[data-theme="dark"] .user-btn{...}` вычеркнут только `.user-btn` из списка селекторов, `.note.pinned` (живой, используется в `app.js` для закреплённых заметок) остался |
| `.btn-plain` (+ тёмная тема) | универсальная «прозрачная» кнопка | нигде не навешивается ни в разметке, ни в JS |
| `.empty-state .es-emoji` | эмодзи в пустом состоянии | класс `es-emoji` нигде не используется (сам `.empty-state` — живой, используется без вложенного эмодзи) |

Итого 15 правил уменьшили `styles.css` на ~1.1 КБ. `node build.js` и
`page.coverage` после удаления подтверждают: 525 листовых правил вместо 540,
фигурные скобки сбалансированы (565/565).

## Проверка «ничего не отвалилось» (шаг 4)

`node tools/shots.js after-deadcss` — снимки сравнены с `docs/superpowers/baseline/before/`
глазами, по всем 32 парам (phone/desk × dark/light × 8 экранов).

Ни один из удалённых классов не применяется ни в реальном приложении, ни в
`tools/demo.html`/`demo-fixtures.js` (те же grep дали ноль совпадений) — то
есть визуальное отличие в принципе было невозможно, но сверка сделана не
только по этой логике, а и по факту.

Найдены два отличия «до/после», оба — **не из-за CSS**, а уже задокументированная
в `docs/superpowers/baseline/README.md` неустойчивость самого стенда:

- на части снимков модалка «Тебе назначили свидание!» отпечатывается
  дважды (см. README, раздел про двойной отпечаток) — воспроизводится
  один в один и на неизменённом `styles.css` (проверено: временный откат
  `styles.css` к `git show HEAD:styles.css` и повторный прогон того же
  экрана дал точно такое же удвоение);
- на части снимков (начиная с settings/photos) всплывает или не всплывает
  тост «Фото не синхронизируются: хранилище недоступно» — тоже про таймингом
  асинхронной проверки, не про CSS.

Экраны без этих двух артефактов (например `phone-light-home`) — побайтово
идентичны «до» и «после». Учитывая, что модалка перекрывает большую часть
некалендарных экранов (см. Task 2 / README), сверка велась по видимым
областям — шапка, домашний экран целиком, края и углы остальных экранов —
как и оговорено в задании, а не как полный аудит того, что модалка и так
всегда закрывала.

## Кандидаты — не удалены (шаг 5)

227 правил из 525 не сработали ни разу на стенде. Подавляющее большинство —
объяснимо: стенд не наводит курсор, не тащит карточки, не открывает
модалки кликом, не входит в режимы выбора/редактирования и не создаёт
пустых списков или недогруженных фото. Ни одно из них не входило в список
спеки, поэтому здесь — фиксация, а не удаление; полный список с номерами
строк — `docs/superpowers/baseline/css-coverage-unused.json`.

| Категория | Примеры | Почему не сработало на стенде |
|---|---|---|
| `:hover` / `:active` / `:focus-visible` (≈45 правил) | `.nav-btn:hover`, `.btn:hover`, `.cal-nav:hover`, `.dp-day:hover`, `.lb-btn:hover`, `.wish:hover`, `.ev-btn:hover`, `.check:hover`, `:focus-visible` и тёмные варианты | автообход не двигает мышь и не фокусирует клавиатурой — состояние есть, курсора нет |
| Drag & drop (≈12 правил) | `.note.dragging`, `.sortable-ghost`, `.sortable-fallback`, `.drag-ghost`, `body.uni-dragging`, `.photo.drag-over`, `.album-chip.drag-over` | классы навешивает `05-dnd.js`/SortableJS только во время реального перетаскивания |
| Модалка «добавить/изменить дату» (`.event-modal` и вложенные, ≈20 правил) | `.ev-head`, `.ev-grid`, `.ev-save`, `.event-modal input[type=date]` | модалка открывается кликом по «Назначить свидание» / карточке дня — стенд по ним не кликает |
| Кастомный date-picker `.dp-*` (≈18 правил) | `.dp-head`, `.dp-grid`, `.dp-day.picked`, тёмная тема | открывается кликом по `input[type=date]`, стенд его не открывает |
| Модалка «Лейблы» (`.label-*`, ≈9 правил) | `.label-row`, `.label-swatch`, `.label-apply-list` | отдельная модалка, открывается из раздела «Фото», не на пути обхода |
| Лайтбокс фото (`.lb-*`, ≈12 правил) | `.lb-stage`, `.lb-arrow`, `.lb-close`, `.lb-pin.active` | открывается кликом по фото, стенд фото не открывает |
| Режим «Выбрать» на фото (`.sel-*`, `.photo.selected`, ≈8 правил) | `.sel-photo`, `.sel-count`, `.sel-bar .btn` | включается вручную кнопкой «Выбрать», стенд её не нажимает |
| Пустые состояния (≈2 правила) | `.empty-li`, `.ev-filter-level:empty` (`.rem-empty`/`.dates-empty` удалены фазой 9 — списки/свидания используют общий `emptyState()`, `src/20-theme-nav.js:99`) | фикстуры стенда (`demo-fixtures.js`) всегда с данными, пустой список не воспроизвести без правки фикстур |
| Состояния календаря (`.cal-cell.selected/.in-span`, `.date-evt.date-done`, ≈10 правил) | требуют выбранного дня/диапазона или завершённого свидания на конкретную дату | обход не кликает по дням календаря |
| «Наша история» / таймлайн (`.tl-*`, `.history-otd`, `.hs-otd-chip`, `.hs-shuffle:*`, ≈12 правил) | нужны сохранённые фото/события «в этот день» в других годах — таких данных нет в фикстурах | |
| Анимации по действию (`.confetti`, `[data-motion]`-оверрайды, `::view-transition-*`, ≈8 правил) | конфетти при сохранении, переключатель анимаций, View Transitions при смене темы — простой обход экранов их не запускает | |
| Редактирование заметки/списка (`.note-editor`, `.note-edit-btns`, `.list-name-editor`, `.btn-sm`, +тёмная тема, ≈6 правил) | требуют входа в режим редактирования | |
| Скелетон/недогруженное фото (`img[data-photo-src]`, `.photo:has(img[data-photo-src])`) | фикстуры отдают уже готовые data-URL, окна «ещё не догружено» физически не возникает | |
| `@font-face` (2 правила) | ложное срабатывание самого CSS Coverage — `@font-face` не «применяется» к элементу как обычное правило, хотя шрифт Nunito визуально используется на каждом снимке | |

### Отдельно: похоже на мёртвый код той же «эпохи сейфа», но не в списке спеки

`.auth-card input[type=password],.auth-card select` и `.auth-card select`
(styles.css) — нацелены на `input[type=password]`/`select` внутри
`.auth-card`, а в текущей разметке гейта (`index.html`, `#gateScreen`)
внутри `.auth-card` таких элементов больше нет (только логотип, заголовок,
`.auth-sub`, кнопка входа через Google и `.auth-err`). По всем признакам —
такой же мёртвый остаток старого гейта, как и удалённые `.auth-who` и
соседи. Не тронуто, потому что не входит в список из спеки (раздел 4.1
называет только 11 конкретных классов) — оставлено на фазу 10 вместе с
отдельной проверкой (вдруг где-то ещё есть `.auth-card` с паролем, которую
`grep` не поймал из-за динамической генерации).

## Итог

- Удалено: 15 CSS-правил (11 названных спекой классов + их тёмные варианты).
- Осталось кандидатами: 227 правил, см. `css-coverage-unused.json` — работа
  для фазы 10, когда будет видно, какие экраны/режимы редизайн вообще
  сохраняет.
- Инструмент `tools/css-coverage.js` — одноразовый, но рабочий; при повторном
  запуске (после `node tools/serve.js`) даёт актуальный список заново.
